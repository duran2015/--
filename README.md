# 可鹿心理：咨询师端 + 用户端完整演示版

这是本次在本地实际演示的双端组合版本，不是两个互不关联的旧原型：

| 应用 | 目录 | 技术 | 默认地址 |
| --- | --- | --- | --- |
| 咨询师端 | `counselor-web/` | React 19、Vite、Material 3 | `http://localhost:4311/counselor` |
| 用户端 | `client-flutter/` | Flutter Web、Material 3 | `http://localhost:4312` |

仓库的统一 Web 服务还会把同一份 Flutter 用户端发布到
`http://localhost:4311/client/`。该路径不是旧 React 用户原型。

两端当前通过统一的 Mock 业务字段、订单状态、工作流节点和 IM 卡片规则完成演示。真实数据库、支付、音视频、IM、转录及 AI 服务由 Builder 按本文末尾的边界接入。

## 拉取后运行

### 最简单的一键启动（推荐给 Gemini、Trae 和 Builder）

```bash
npm install
npm run dev
```

然后打开：

- 咨询师端：`http://localhost:4311/counselor`
- 用户端：`http://localhost:4311/client/`

根目录的常规 `dev/build/start` 命令已经固定到正确的双端交付入口，
不会再把咨询师 React 工程中遗留的旧 `/client` 页面当成用户端。

仓库内嵌的 Flutter 用户端使用 `API_ENV=mock` 和
`DEV_AUTO_LOGIN=1` 构建，因此 Release 演示页面也会自动进入用户端，
并展示咨询师会话、普通消息、系统通知和各业务节点卡片。只有改用
`API_ENV=live` 重新构建时才会连接真实接口并关闭这些 Mock 数据。

### 1. 咨询师端（4311）

```bash
cd counselor-web
npm install
npm run dev
```

打开：`http://localhost:4311/counselor`

也可以在仓库根目录运行：

```bash
npm run setup:counselor
npm run dev:counselor
```

### 2. 用户端（4312）

```bash
cd client-flutter
flutter pub get
flutter run -d web-server \
  --web-hostname 0.0.0.0 \
  --web-port 4312 \
  --dart-define=API_ENV=mock \
  --dart-define=DEV_AUTO_LOGIN=1
```

打开：`http://localhost:4312`

用户端已经补齐标准 `web/` 平台目录，不需要模拟器，也不需要重新执行 `flutter create`。

## 本次相对原 Flutter 双端版本的完整功能调整

### 一、统一账号和双身份

- 首次注册默认进入用户端，不强迫所有用户先选择身份。
- 登录页提供弱提示的“我是咨询师”入口。
- 未入驻用户选择咨询师身份后进入入驻和资质审核流程。
- 已具备双身份的账号记录最近使用身份，下次登录自动恢复。
- 用户端和咨询师端都保留身份切换、退出登录、注销账号、关于我们和意见反馈。
- 账号主体、用户资料、咨询师资料和最近身份分别保存。

### 二、用户端真人咨询入口

- “真人咨询”从首页快捷宫格中拆出，成为独立底部导航。
- 复用并优化原 Flutter 咨询师列表和详情页，而不是重写一套不一致页面。
- 列表优先展示用户关心的信息：擅长领域、专业资质、咨询风格、可约时间、咨询方式、经验、评分和起步价格。
- 咨询师详情展示完整介绍、资质、受训经历、工作取向、服务对象、评价、SKU 和可服务时间。
- 用户可以从咨询师详情选择 SKU、时段并创建预约。

### 三、预约、订单和工作流分层

- 双端统一订单字段、咨询师/用户头像、SKU、预约时间、金额和操作规则。
- 订单状态仅表达交易和履约：待支付、待咨询师确认、待咨询、咨询中、已完成、已取消、已退款。
- 前序资料、进入咨询室、等待回顾、查看回顾和评价属于工作流节点，不再伪装成订单状态。
- Mock 数据覆盖支付、咨询师确认、前序资料、咨询室、等待回顾、查看回顾和评价等完整阶段。
- 咨询师工作台每个案例只展示当前节点、说明、预约时间和当前按钮，不再展开臃肿的全流程时间线。
- 用户端订单列表和详情采用与咨询师端一致的 Material 3 信息层级，但按用户角色展示内容和动作。

### 四、预约规则、取消、退款和改期

- 用户下单和订单详情均展示咨询师预约规则、可服务时间、最小预约时长和取消规则。
- 开诊前 24 小时以上取消可全额退款；不足 24 小时按规则扣费；服务开始后不可退款。
- 改期改为两阶段业务流：
  1. 用户在订单详情底部点击“申请改期”，与“取消预约”并列，只选择改期原因。
  2. 申请发送给咨询师，确认前原预约仍有效。
  3. 咨询师同意后，用户底部按钮变为“选择新时间”。
  4. 用户再打开排期控件，从咨询师可用时间中选择新时段。
- Mock 同时提供可申请、申请待确认、咨询师已同意三类记录。

### 五、IM 会话和业务消息卡片

- 双端统一会话列表头像、聊天头部、输入栏、消息气泡和卡片字段。
- 安全提醒使用轻量警示区域，不具有业务交互。
- 状态通知使用居中弱层级标签，表达预约创建、咨询结束等客观结果。
- SOP 动作卡属于订单/会话公共状态，居中展示，不归属于任一聊天方。
- 来访者和咨询师气泡按“我/对方”角色投影，避免两端左右方向和颜色相反。
- 预约、付款、接单、填写资料、进入咨询室、回顾分享和评价均提供对应 IM 卡片或通知。
- 用户图片消息限制显示尺寸，避免大图撑满会话。
- 咨询师头像在会话列表、聊天头部、消息气泡、订单和咨询室保持一致。
- 会话支持举报和拉黑；AI 小鹿会话不展示举报，保留字体、字号、音色、语速和自动朗读设置。

### 六、系统通知

- 用户端和咨询师端均提供独立系统通知入口和通知会话。
- 通知类型包括订单/行程动态、平台活动、优惠信息、账户与安全、服务跟进和 AI 助手。
- 类型、图标、标题、正文、操作和跳转目标均按后台可配置结构设计，前端使用 Mock 数据。
- 用户可关闭活动、优惠等非必要通知。
- 订单履约、安全和必要合规通知不可被普通营销开关误关。

### 七、语音和视频咨询室

- 用户端咨询室迁移到咨询师端当前版本的统一布局，并按身份删减咨询师专属能力。
- 双端统一会议号、预约类型、通话计时、头像、网络状态和底部控制舱。
- 支持语音和视频两种 Mock 会议室状态。
- 用户端只保留麦克风、扬声器/摄像头、聊天和挂断等必要操作。
- 咨询师端额外提供实时转录、AI 重点、私人笔记、情绪反馈和风险上报。
- 语音通话持续消费语音情绪识别接口结果。
- 视频通话持续消费多模态情绪识别接口结果；摄像头不可用时降级为语音信号。
- 情绪只展示接口返回值、置信度、来源和时间，前端不自行给用户下诊断。
- 咨询师侧辅助面板可滚动，用户头像与订单/IM 中的同一用户保持一致。

### 八、咨询结束、回顾、作业和评价

- 结束咨询不再直接跳首页。
- 咨询师进入独立的会后页面，参考实时转录、AI 提取重点、咨询前资料和私人记录。
- 咨询回顾包括写给用户的寄语/小结、推荐会后行动和下次探讨方向。
- 咨询师可以稍后完成；未确认回顾前结算保持锁定。
- 确认后回顾以 IM 卡片和待办推送给用户。
- 用户查看完整回顾和作业后进行评价；咨询师也可以完成对应评价。
- 不再把“复盘”作为用户业务节点，统一使用“确认总结/咨询回顾”。

### 九、用户资料和授权支持档案

- 用户端“我的”页面提供明确的“编辑资料”入口，头像、昵称区域也可点击。
- 可编辑头像、昵称、个人签名、性别、年龄段、城市和职业/生活阶段。
- 头像仅接受图片且限制为 5MB。
- 用户信息按用途拆成三组：
  - 基础资料：账号和必要联系。
  - 咨询偏好：咨询师匹配和排序。
  - 支持档案：经用户授权后提供给本次咨询师。
- 支持档案默认仅自己可见，授权后生成本次预约快照，避免后续修改污染历史订单。
- 引导发生在首次首页、浏览咨询师、预约完成、咨询前 24 小时、咨询结束和长期未维护时，不在注册登录时强制填写量表。

### 十、咨询师资料、头像审核和入驻签约

- 咨询师可编辑姓名、头衔、介绍、资质、教育、受训、咨询取向、擅长领域、服务方式和服务对象。
- 咨询师头像变更需要平台审核，状态包括已通过、审核中、未通过。
- 审核期间继续展示旧头像；驳回时显示原因并允许重新上传。
- 增加咨询师入驻、资质申请和审核流程。
- 增加平台入驻协议，状态包括待签约、签约中、已签约，并展示协议版本、签字人和签署时间。
- “我的”补齐历史订单、收入提现、SKU、排班、预约规则、平台规则、账户安全和退出登录。

### 十一、咨询师私域运营定位

- 咨询师可分享预约入口承接自有用户，也可录入线下案例统一管理。
- 平台提供统一订单、预约、档案、IM、咨询室、回顾和评价工具。
- 当前产品规则中私域订单不额外抽佣，支付通道费用按实际发生处理。
- 用户明确授权后，可做服务跟进和有限频率的营销触达；用户可关闭营销通知。

### 十二、AI 小鹿体验

- AI 会话头部压缩为类似现代 AI 助手的紧凑导航，明确“内容由 AI 生成”。
- AI 消息不重复显示头像，减少视觉噪音。
- 内置用户与小鹿的连续 Mock 对话（呼吸放松、焦虑表达、共情回应和最小行动），用于直接演示双方消息样式。
- AI 会话示例图片在手机端按比例缩放，Web 宽屏最大 240px，不再挤走上下文。
- 输入栏、图片尺寸、快捷建议和语音入口按 Material 3 优化。
- 恢复字体大小、朗读音色、语速和自动朗读设置。

## Builder 需要接入的后端能力

当前仓库用于产品和业务流演示，以下能力需替换 Mock：

- 统一账号、短信登录、第三方登录、双身份、咨询师入驻和权限。
- 用户资料、咨询偏好、支持档案、授权快照和隐私审计。
- 咨询师、资质、头像审核、协议签署、SKU、排班和预约规则。
- 订单、支付、退款、取消、两阶段改期、收入、提现和结算。
- IM 普通消息、系统通知、SOP 卡片、待办、已读状态、举报和拉黑。
- 音视频房间、进房 Token、实时转录、语音/多模态情绪识别和风险事件。
- AI 重点、咨询师私人笔记、咨询回顾、作业、双向评价和结算联动。
- 运营后台通知模板、频率、用户开关和营销授权。
