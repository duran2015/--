# 2026-08-07 咨询室持续情绪反馈更新说明

## 更新背景

咨询师在较长时间的语音或视频咨询中，需要持续了解来访者可能呈现的情绪状态和变化趋势。本次更新为咨询师端咨询室补充了持续情绪反馈原型，并明确前端 Mock 与真实识别接口的边界。

情绪识别结果只用于辅助咨询师观察，不作为心理诊断，不直接触发危机上报，也不向普通用户展示。

## 本次新增功能

### 1. 咨询室情绪状态提示

- 咨询师进入正式通话后，会议计时器下方显示“情绪动态”状态 Chip。
- 状态示例包括“分析中”“平稳”“紧张上升”“紧张持续”“逐渐放松”和“趋于平稳”。
- 点击状态 Chip 可直接打开右侧 AI 咨询助手，并定位到情绪动态详情。
- 用户端不显示情绪识别状态。

### 2. AI 侧栏情绪动态卡片

原有固定文案“实时情绪洞察”升级为结构化的“情绪动态”卡片，包含：

- 当前接口返回的情绪状态和趋势描述；
- 置信度等级；
- 最近一段时间的趋势图；
- 语音、表情和姿态等实际有效识别来源；
- 满足条件的关键变化节点；
- “AI 结果仅用于辅助观察”的固定提示。

情绪详情与实时转录、咨询师私密笔记继续放在同一个 AI 侧栏中，避免增加新的独立入口。

### 3. 持续变化轻提醒

- 单个识别窗口不会直接弹出提示。
- 只有情绪变化持续一段时间并达到置信度要求后，才显示低干扰 Snackbar。
- 提醒示例为“系统观察到紧张状态已持续约 2 分钟”。
- 咨询师可以查看详情或关闭提醒。
- 同类提醒有冷却机制，避免在长时间咨询中频繁打断。
- 情绪模型不会自动打开或提交危机风险上报。

### 4. 语音与视频场景

#### 语音咨询

- 情绪信息来源标记为“语音语调”。
- 保留现有语音咨询头像主舞台和低干扰视觉效果。

#### 视频咨询

- 增加正式通话中的独立视频舞台，不再继续使用等待状态的参与者卡片。
- 情绪信息来源可包含“语音 + 表情 + 姿态”。
- 情绪标签不会覆盖在人脸上，也不会显示人脸检测框。
- 视频信号不可用时，可降级为语音来源，并明确显示当前有效来源。

### 5. 会后“确认总结”衔接

- 满足条件的显著情绪事件会转换为可追溯的 AI 情绪证据。
- 证据包含事件时间、描述、置信度和来源事件 ID。
- 情绪证据随本次咨询快照进入会后“确认总结”。
- 用户可见总结不会自动包含模型结论，必须由咨询师审核并重新表述。
- 情绪识别是否可用不影响总结提交和咨询师结算流程。

### 6. 结束会议页面修复

- 修复结束会议后页面未完整覆盖视口的问题。
- 结束页现在与通话页使用一致的全屏固定层。
- 不再出现顶部裁切或底部露出工作台内容的情况。

## 数据来源说明

### 真实环境

用户情绪由语音情绪识别服务或多模态情绪识别服务判断。前端不分析音频、视频或用户情绪，只消费平台后端返回的标准化结果。

标准化响应包含：

- `labelCode`：识别服务返回的状态编码；
- `labelDisplay`：页面展示文案；
- `trendCode`：趋势编码；
- `trendDisplay`：趋势说明；
- `confidence`：置信度；
- `sustainedSeconds`：持续时间；
- `sources`：当前有效识别来源；
- `timeline`：趋势时间线；
- `significantEvent`：满足聚合规则后的显著事件。

前端的职责仅包括：

1. 将标准化响应映射为 Material 3 组件；
2. 处理加载、降级、断流和不可用状态；
3. 展示咨询师可见的趋势和提醒；
4. 将显著事件关联到会后总结证据。

### 当前原型

当前项目尚未连接真实语音或多模态识别服务，因此使用独立的 Demo Mock Provider 模拟同一份接口响应。

Mock 只用于展示以下交互：

`分析中 → 平稳 → 紧张上升 → 紧张持续提醒 → 逐渐放松 → 趋于平稳`

Builder 接入真实服务时，应替换 Mock Provider，不需要修改主界面、AI 侧栏和总结证据组件。

## Builder 后续实现要点

- 建立会话级情绪识别 WebSocket 或事件流。
- 后端负责供应商结果标准化、窗口平滑、持续时间判断和提醒冷却。
- 前端优先消费聚合后的趋势与显著事件，不直接消费高频原始帧结果。
- 语音与视频共用一套前端展示协议，通过 `sources` 区分有效模态。
- 保存显著事件的时间范围、来源窗口、模型版本和置信度。
- 情绪数据只允许当前咨询师及明确授权人员读取。
- 原始音频、视频和视频帧不进入普通业务库。
- 情绪识别异常不能中断音视频咨询、会议结束、总结或结算。
