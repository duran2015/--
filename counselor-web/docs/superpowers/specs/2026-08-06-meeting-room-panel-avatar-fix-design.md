# 咨询室侧栏滚动与头像一致性修复设计

## 背景

咨询师进入视频咨询室并打开 AI 咨询助手后，侧栏被拆成内容区和固定笔记区。内容区会被 Flex 布局压缩到刚好容纳可见内容，侧栏自身没有纵向溢出，因此用户在洞察、转录或笔记区域滑动时无法浏览完整内容。

咨询室同时仍从旧版 Mock 字段 `userName`、`avatar` 读取来访者资料，而咨询师订单和客户档案使用 `clientName`、`clientAvatar`。字段来源不同导致会议室回退到默认“小鹿用户”头像，与订单中的咨询用户不一致。

## 已批准方案

采用方案 A：

1. AI 咨询助手保留固定页头，将实时洞察、转录流和咨询笔记放入同一个 `overflow-y-auto` 内容区，形成连续的纵向滚动体验。
2. 会议参与者资料通过单一解析函数获得，优先使用订单标准字段 `clientName`、`clientAvatar`，同时兼容旧字段 `userName`、`avatar`，最后才使用默认资料。
3. 不改变会议状态、转录 Mock、笔记编辑、结束会议和复盘流转。

## 数据流

咨询师端传入的当前订单是会议室来访者资料的唯一业务来源：

`activeLiveOrder -> resolveMeetingClient(order) -> VoiceCall otherName/otherAvatar`

用户端仍展示咨询师资料，不受本次改动影响。

## 交互与布局

- AI 助手页头固定在抽屉顶部，关闭按钮始终可见。
- 页头以下仅保留一个纵向滚动容器。
- 洞察、转录和笔记按现有顺序排列；咨询笔记不再作为独立固定页脚。
- 转录卡片按内容自然增高，不再创建与外层竞争手势的嵌套滚动区。
- 保持现有 Material 3 圆角、颜色、间距和阴影。

## 验证

- 单元测试覆盖标准订单字段、旧字段兼容和默认资料回退。
- 真实浏览器验证移动端高度下侧栏内容至少产生 80px 的滚动距离，滚动后 `scrollTop` 至少达到 80px。
- 真实浏览器验证会议室来访者姓名和头像 URL 与当前订单一致。
- 全量执行测试、TypeScript 类型检查和生产构建。
