# 咨询师工作台串行业务旅程设计

## 目标

工作台不再将同一订单的多个待办平铺成互不关联的行。每笔咨询订单展示一张来访者旅程卡，固定呈现：

`确认预约 → 查阅资料 → 开始咨询 → 确认总结`

已完成节点显示勾选，当前节点展开说明和唯一操作按钮，后续节点锁定。每笔订单独立成链；同一来访者的不同场次不合并，避免资料、会谈和总结串场。

## 节点语义

| 节点 | 工作流任务 | 当前操作 | 完成条件 |
| --- | --- | --- | --- |
| 确认预约 | `confirm_booking` | 确认 | 预约已确认 |
| 查阅资料 | `review_intake` | 查阅 | 咨询师已处理前序资料；若用户未填写则显示“无需资料”并视为跳过 |
| 开始咨询 | `enter_session` | 进入 | 会谈已结束 |
| 确认总结 | `complete_session_review` | 确认总结 | 临床总结和用户回顾已提交 |

每张卡在任意时刻最多有一个当前节点。即使底层 Mock 同时创建“查阅资料”和“开始咨询”任务，也只开放顺序更靠前的节点，后续节点保持锁定。

## 移除咨询师成长节点

`counselor_reflection`、专业自评和“咨询师复盘”属于咨询师成长能力，不属于当前 MVP 业务闭环：

- 会谈结束只创建一个咨询师任务：`complete_session_review`。
- 总结提交仅校验临床总结和用户回顾，不再要求专业自评。
- 结算只被确认总结阻塞，不再被成长型复盘阻塞。
- 总结页面移除“咨询师复盘”页签，标题统一为“咨询总结”。
- 旧版 LocalStorage 中已有的 `counselor_reflection` 任务在加载时过滤，避免旧数据继续出现在工作台。
- `counselorReflection` 草稿字段暂时保留在数据结构中用于向后兼容，但前端不展示、不校验、不提交为当前业务要求；Builder 将其标记为未来督导/成长扩展字段。

## 工作台交互

业务待办区域的计数表示“当前需要处理的订单链数量”，而不是原始任务条数。

每张旅程卡包含：

1. 来访者头像、姓名、预约日期和时段。
2. 四节点横向进度轨道，使用 Material 3 色彩和圆形状态图标。
3. 当前节点的状态说明、结算提示和主操作按钮。
4. 已完成节点可读但不可重复操作；后续节点显示锁图标且不可点击。

已没有当前待办的订单不显示；所有订单链完成时显示“所有业务待办已完成”。

## 状态投影边界

新建纯函数从 `Order[]` 和 `WorkflowTask[]` 生成 `CounselorJourney[]`。组件只负责渲染和把当前节点操作映射到现有回调，不自行推断任务顺序。

投影规则：

1. 过滤咨询师任务、已移除的成长任务和已完成全部业务节点的订单。
2. 按固定阶段顺序查找首个未完成任务，设为 `current`。
3. 当前节点之前的业务节点为 `completed`；未填写前序资料时，“查阅资料”为 `skipped`。
4. 当前节点之后统一为 `locked`。

## 验证

- 工作流测试证明结束会谈只创建一个总结任务，空白专业自评不阻塞提交，旧成长任务可被规范化移除。
- 投影测试覆盖确认预约、查阅资料、无资料跳过、开始咨询、确认总结和同一用户多订单独立成链。
- 总结进度只统计临床总结与用户回顾两部分。
- 真实页面验证每张卡只有一个可操作按钮、后续节点锁定、页面不再出现“复盘”或“专业自评”。
- 全量测试、TypeScript 类型检查和生产构建通过。
