# 2026-08-07 用户侧咨询业务闭环更新说明

## 更新目标

本次根据咨询师端近期对 IM、订单、订单操作、会议室和会后总结的调整，补齐用户端对应的连带流程。两端现在共享同一条业务状态链，而不是各自使用独立页面文案。

## 用户侧完整流程

`预约申请/支付 → 咨询师确认 → 选填咨询前资料 → 进入咨询室 → 等待咨询师确认回顾 → 查看咨询回顾 → 评价咨询师`

## 主要修改

### 1. 统一用户当前事项

新增用户侧状态投影，订单列表、订单详情、首页和 IM 使用同一份状态与操作：

- 待支付：继续支付；
- 待咨询师确认：等待确认；
- 预约已确认但未填资料：填写咨询前资料；
- 资料已填或已跳过：进入咨询室；
- 咨询结束但总结未提交：等待咨询师确认回顾；
- 总结已分享：查看咨询回顾；
- 回顾已读：评价咨询师；
- 评价完成：查看已归档回顾。

兼容咨询师确认后产生的 `scheduled` 状态，避免用户端将已确认预约误显示为退款或异常。

### 2. 首页联动

用户首页新增“我的咨询”当前事项卡，展示最近一笔有效咨询的当前节点。点击后进入该订单详情，不在首页展开复杂流程。

### 3. 订单列表与订单详情

- 订单列表状态文案和主操作由统一状态投影生成。
- 订单详情增加 Material 3 当前事项卡。
- 根据当前节点提供继续支付、填写资料、进入咨询室、查看回顾或评价按钮。
- 等待咨询师总结时不提前开放评价。

### 4. IM 联动

- 咨询会话的副状态与订单当前事项保持一致。
- 咨询师提交总结后，用户收到“本次咨询回顾”卡片。
- 点击卡片会绑定正确订单、完成“查看回顾”待办并打开对应回顾。
- 多笔订单之间不再使用其他订单的总结作为兜底内容。

### 5. 会前资料

- 用户提交咨询前资料后，同时更新订单资料和 `complete_intake` 待办。
- 资料仍为非强制环节；真实后端应支持明确的“跳过”状态。

### 6. 咨询室权限与结束流程

- 用户端隐藏咨询师专用 AI 助手入口。
- 用户结束会议后返回预约详情，不再立即跳转评价。
- 系统进入“等待咨询师确认回顾”状态。
- 咨询师确认总结后，用户才依次查看回顾并评价。

### 7. 回顾与评价解耦

- “本次咨询回顾”页面只展示用户可见总结、行动建议和下次计划。
- 评价移动到独立页面，在用户阅读回顾后开放。
- 修复评价选择“否/没帮助”时被误判为未填写的问题。
- 评价任务严格关联当前订单，不再误完成其他订单的评价待办。

## Builder 对接要求

- 后端返回用户订单的确定性当前节点或足够投影该节点的订单、任务和总结状态。
- 首页、订单、IM 和推送通知必须引用同一个 `orderId`、`sessionId`、`draftId` 和任务状态。
- `read_session_recap` 完成后才能开放 `review_counselor`。
- 用户端只返回 `clientSummary`，不得返回临床总结、咨询师私密笔记、完整转录和内部风险复核。
- 用户先结束会议时，后端仍需创建或保留咨询师的总结任务；用户侧只进入等待状态。
- 所有操作需按订单幂等，禁止使用“任意一个未完成任务”作为兜底。
